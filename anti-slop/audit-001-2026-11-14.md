# Anti-slop audit 001, Revisio web + native copy

Date: 2026-11-14
Mode: after (session override)
Scope: landing page, app shell, learner-facing copy on web, mirrored copy on both phones
Not in scope: legal page bodies (deliberate formal voice, reviewed separately), admin screens

## Direction and dials (R-37, Block 3)

Direction exists: `docs/UI-SYSTEM.md` positions the product as "a quiet study instrument with a
ladder", principle 5 being "Plain words ... The interface never congratulates itself".

Reading this as: a study tool for GCSE, A-level and university learners, in a paper-and-ink
instrument language, dial **ENERGY 1 / RHYTHM 2 / MOTION 1**.

Evidence the output matches: the landing is five sections with different compositions (hero,
interactive forgetting curve, an asymmetric 2x2 grid where one card spans both rows, a dark ladder
band, a close). It is not the hero + three identical cards + testimonials template. One accent,
scoped to the ten tier metals and read by exactly three components.

Verdict on Block 3: PASS. Dials are set, there is one focal point per screen, whitespace carries the
rhythm, the accent is deliberate, and the ladder is the identity motif.

## Findings

### 1. The landing states something the product contradicts (HIGH, R-36, C-5)

`src/app/page.tsx` ("A record of what stuck") says:

> Thirty rungs across ten tiers, earned from everything you have ever reviewed. They never reset.

`src/domain/seasons.ts:11` says the opposite:

> The rank is seasonal. It resets every season, and the rank you held when the clock ran out is
> written down, shown off, and paid. The season record is permanent. It is the one thing that never
> resets.

`AGENTS.md` agrees with the code: "Rank is SEASONAL", and the seasonal rank is the rank actually
earned. So the sentence is a fabricated claim (R-36) and fails evidence-over-claims (C-5), not just
a wording problem. It is also the only product claim on the page a user can check against their own
experience after ninety days.

This needs an owner decision, not a silent rewrite: either the copy follows the seasonal model, or
the ladder is meant to be lifetime and the seasons code is wrong.

### 2. Prose em dashes remain in learner-facing text (HIGH, R-02)

R-02 bans the character in any text. Six instances are prose, not data:

| File | Text |
|---|---|
| `src/lib/pronouns.ts:57` | "Pronouns are letters and a few marks — slash, hyphen, comma, brackets." |
| `src/components/AuthForm.tsx:87` | "before the first sign-in — you will get an email once it is approved." |
| `src/app/(app)/library/ClozeMarking.tsx:266` | "Overrides the wider setting for ..." (placeholder dash is separate) |
| `src/app/api/v1/content/merge/route.ts:36` | "Nothing to move — that topic was already empty." |
| `src/app/api/v1/import/route.ts:29` | "That file is over 5 MB — split it and import the parts." |
| `src/app/api/v1/settings/unsubscribe/route.ts:115` | "Messages about your account itself — verification, password resets — still arrive" |

Document titles also carry one, which is visible in the browser tab and in shares:
`src/app/layout.tsx:29` ("Revisio — Learn it once"), `privacy/page.tsx:19`, `cookie-policy/page.tsx:21`,
`terms/page.tsx:17`, `accessibility/page.tsx:6`, `u/[handle]/page.tsx:35`.

Both phones carry one in a learner-facing string: `Copy.kt:105` and `Copy.swift:100`
("$pct% today — this is your best gear."). These are parity-checked files, so a change here means
`npm run vectors:copy` plus both native suites.

### 3. The em dash as an empty-value glyph needs a decision (MEDIUM, R-02)

`'—'` is used to mean "no value" in `dashboard/page.tsx:222`, `insights/InsightsBody.tsx:87` and
`:113`, `insights/StrengthCard.tsx:64`, `rank/RankView.tsx:309`.

This is a typographic placeholder rather than prose, and removing it changes tables and stat cards,
so it should not be swept with finding 2. Either keep it and record the exemption, or switch to
"Not yet" where the cell has room.

### 4. Uppercase tracked eyebrow labels (MEDIUM, R-06)

`.t-eyebrow` (`globals.css:492`) is 12px, weight 700, `letter-spacing: 0.1em`, uppercase, and is used
for section labels such as "Memory, on a schedule" and "The ladder". R-06 forbids uppercase labels
with wide tracking as a default without a written reason. At 0.1em this is mild and it is consistent
across the site, so the cheap fix is one line in `docs/UI-SYSTEM.md` recording why the label voice is
uppercase, not a redesign.

### 5. Arrow glyph on the primary CTA (LOW, R-08)

`src/app/page.tsx` close block renders "Start free" with `Icon name="next"`. One arrow on the main
action is defensible, but R-08 asks for the purpose to be written down. One line in UI-SYSTEM, or
drop it.

### 6. Icon set is Lucide by house convention (MEDIUM, R-04)

`src/components/ui/icons.tsx:4` documents "one icon set (lucide), one stroke weight, one grid", and
every glyph is reached through a semantic key (`review`, `next`, ...) rather than imported at call
sites. That is a deliberate system rather than a default library look, so this passes once the
reason is recorded in `docs/UI-SYSTEM.md`. Flagged because R-04 names Lucide explicitly.

### 7. No click-through of every control in this pass (HIGH, R-35)

The evidence behind this audit is the 24-screen app audit (`artifacts/app-audit/2026-11-14T01-49-57`,
0 FAIL, 0 WARN, 0 axe) plus the production public suite (105 checks, 0 axe, 0 page errors). Neither
clicks every control and reports what happened. R-35 treats an unrecorded click-through as not
verified, so this stays OPEN until someone drives each control on the built site.

### 8. Per-screen state coverage not re-verified (MEDIUM, R-27)

Empty, loading and error states exist as components (`EmptyState`, skeletons) and were exercised by
earlier suites, but this pass did not open each data screen in each state. Report as unverified
rather than passed.

  `profile.ts` (grep returned nothing).
- R-17: the only numbers on the landing are 30 rungs and 10 tiers, which match `domain/ranked.ts`
  (ten tiers, three divisions).
- R-24: the twelve audited routes exist and were reached; no link to a missing page appeared in the
  audit run.
- R-25: 0 axe violation instances at light and dark across every public route, and 0 in the
  app-audit run.
- R-34: both themes audited on every screen.
- R-39 (partial): `cursor: pointer` is set in the base layer, `<html lang="en">` is present, and the
  previous pass lifted small-type action anchors to a 44px floor.
- R-40: no `<img>`, `<video>` or `<iframe>` on the audited screens, so the dimensions and
  `fetchpriority` rules have nothing to bite on.
